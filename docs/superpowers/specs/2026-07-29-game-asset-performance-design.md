# 游戏资源加载性能设计

## 目标

保留“读取存档后只有在游戏资源完成加载或明确失败后才进入游戏”的可靠性，同时消除每次读档都通过公网重复下载大体积 PNG 的等待。

## 方案

- 场景和杨子豪运行时帧图转换为 WebP，并控制渲染源图的最长边为 2048px（地图）或 1536px（角色帧）。角色在游戏中最大绘制尺寸为 264px，场景由 Canvas 缩放；该尺寸保留现有屏幕清晰度。
- 使用新文件名 `-v2.webp`。版本化 URL 允许服务器对 `public/assets/` 返回一年 `immutable` 缓存，而代码、HTML 和 API 保持 `no-cache`，避免发布后页面逻辑陈旧。
- 页面加载时立即在后台启动全部五张场景图预取；现有角色图片也在模块加载时启动下载。用户登录、选择英雄和阅读存档时下载继续进行。
- `startGame` 仍在加载页等待场景与角色资源结束；若已经由浏览器缓存完成，立即进入游戏。图片失败时依旧进入，使用原有 Canvas 回退，不会永久卡住。

## 服务器缓存

- `.webp` 使用 `image/webp` MIME。
- `assets/` 下的版本化图片响应 `Cache-Control: public, max-age=31536000, immutable`。
- 其他静态页面、模块和 API 响应不改为强缓存。

## 验收

- 首次从公网打开后，地图与角色资源在标题/登录期间下载；点击“存档”后不再重新发起已缓存资源请求。
- 五张地图、跑动帧和战斗帧均使用本地 `.webp` URL，服务器返回正确 MIME 和一年 immutable 缓存。
- 清除浏览器缓存后的首次完整下载量显著低于当前 PNG 方案；刷新/再次读取存档时不重新下载版本化资源。
- 资源加载失败时仍可进入，且台子、副本和角色回退绘制可用。
